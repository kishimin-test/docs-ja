## 解決したい課題

公開サイトに広告を表示したいが、広告の実装は以下の点で本体の品質を損ないやすく、無計画に埋め込むと後から取り返しにくい。

- 広告枠の高さが読み込み後に確定すると、本文が押し下げられてレイアウトシフトが発生する
- 外部スクリプトの読み込みが初期表示を遅くする
- 広告配信は利用者の情報を扱うため、同意取得と表示の扱いを決める必要がある
- 外部スクリプトを許可するために CSP を緩めると、SEO Issue やセキュリティ要件と衝突する

## 提案する解決策

広告表示を、レイアウト・性能・同意の観点を満たす形で実装する。

### 決めること

- 広告配信サービス
- 広告を表示するページと配置 (一覧ページ、記事詳細ページ、about ページに出すか)
- 同意管理の要否と方式 (対象地域と配信サービスの要件から判断する)

### 実装

- 広告枠の寸法をあらかじめ確保し、読み込み前後で本文の位置が動かないようにする
- 広告スクリプトを非同期で読み込み、初期表示をブロックしない
- 表示領域に入ってから読み込む (遅延読み込み)
- 広告の読み込みに失敗しても、本文の表示と操作が継続する
- 広告であることが利用者に分かる表示にする
- 外部スクリプトの読み込み元を CSP で明示的に許可し、必要最小限に留める
- prerender した静的 HTML と組み合わせても、広告枠の位置ずれが起きないこと
- 開発環境とテスト環境で実際の広告を読み込まない切り替えを設ける

## 代替案

- **広告を入れない** — 品質と実装コストの面では最良だが、収益化の要件を満たさない。要件として広告表示が指定されているため不採用。
- **記事本文中に広告を差し込む** — 収益性は高いが、読みやすさとレイアウトシフトへの影響が大きい。まずは本文外の固定枠から始める。

## 受入条件

- [ ] 広告配信サービス、表示ページ、同意管理の方式が決定され、記録されている
- [ ] 広告枠の読み込み前後で本文の表示位置が動かない
- [ ] 広告スクリプトが初期表示をブロックしない
- [ ] 広告の読み込みに失敗しても、本文の閲覧と画面遷移が継続できる
- [ ] 広告であることが利用者に分かる表示になっている
- [ ] CSP で許可した読み込み元以外の外部スクリプトが実行されない
- [ ] 開発環境とテストで実際の広告が読み込まれない
- [ ] 同意が必要と判断した場合、同意前に広告が配信されない
- [ ] モバイル幅で広告が本文の可読性を損なわない

## 対象外

- 広告収益の最適化、配置の A/B テスト
- アクセス解析の導入

## 補足

- 依存: public-web 基盤Issue、SEO Issue (CSP と prerender の整合)
