# メディア管理 (画像アップロード・一覧) を実装する

| 項目 | 値 |
| ---- | -- |
| Issue | [#26](https://github.com/kishimin-ai-create/profile-hub/issues/26) |
| 英語タイトル | Implement media management (image upload and library) |
| マイルストーン | v2 |
| ラベル | enhancement,area:admin-web |

---

## 解決したい課題

v1 では記事やプロフィールの画像を URL 指定でしか扱えない。管理者が自分の画像を使うには、別のサービスへアップロードして URL を取得するという外部依存の手順が必要になり、その画像が消えるとサイト側の表示も壊れる。

## 提案する解決策

管理画面にメディア管理機能を実装する。

### 画面

| パス | 内容 |
| ---- | ---- |
| `/media` | アップロード済み画像の一覧、アップロード、削除 |

### 機能

- 画像のアップロード (ファイル選択、ドラッグ＆ドロップ)
- アップロード済み画像の一覧表示 (サムネイル、ファイル名、サイズ、アップロード日時)
- 画像の削除
- 代替テキストの編集
- 記事編集画面とプロフィール編集画面から、アップロード済み画像を選択して挿入する

### 振る舞い

- アップロード中に進捗が分かる表示をする
- 許可外の形式やサイズ超過を、アップロード前にクライアント側でも通知する
- 使用中の画像を削除しようとしたときの扱いを決める (警告する / 参照を検出して防ぐ)
- 削除時に確認ダイアログを表示する
- 一覧が増えてもページングまたは遅延読み込みで一度に全件を読み込まない
- ファイル選択がキーボードのみで操作できる

## 代替案

- **記事編集画面からのみアップロードでき、一覧を設けない** — 実装は減るが、アップロード済み画像の再利用と削除ができない。一覧を設ける。

## 受入条件

- [ ] 認証済み管理者が画像をアップロードでき、一覧に表示される
- [ ] アップロードした画像を記事編集画面から選択して挿入でき、公開サイトで表示される
- [ ] 代替テキストを設定でき、公開サイトの画像に反映される
- [ ] 許可外の形式・サイズ超過のファイルでエラーが表示され、アップロードされない
- [ ] 削除時に確認ダイアログが表示され、キャンセルすると削除されない
- [ ] 削除した画像が一覧から消え、ストレージからも削除される
- [ ] 使用中の画像を削除しようとしたときに、決定した方針どおりの挙動になる
- [ ] 一覧が一度に全件を読み込まない
- [ ] ファイル選択がキーボードのみで操作できる

## 対象外

- 画像のトリミング、リサイズなどの編集機能
- 動画・音声など画像以外のメディア
