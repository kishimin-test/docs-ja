## 解決したい課題

趣味に関する記事を訪問者が読む手段がない。趣味ページは自己紹介サイトにおいて、技術面以外の人物像を伝える役割を持つ。

## 提案する解決策

趣味記事の一覧ページ (`/hobby`) と詳細ページ (`/hobby/:slug`) を実装する。

### 一覧ページ (`/hobby`)

- 公開済みで `type = hobby` の記事を、公開日時の降順で表示する
- 表示項目 — タイトル、抜粋、公開日、タグ
- ページングを適用し、記事が増えても一度に全件を読み込まない
- タグによる絞り込み
- 記事を選択すると詳細ページへ遷移する

### 詳細ページ (`/hobby/:slug`)

- 表示項目 — タイトル、本文、公開日、更新日、タグ
- 一覧へ戻る導線
- 長文でも読みやすい行長・行間にする
- 存在しないスラッグ、または下書き記事のスラッグを指定した場合は 404 を表示する

### 記事本文の描画

- 記事本文は管理者が入力したコンテンツであるため、描画方式を明確にする
- Markdown を HTML へ変換する場合、`script` や `on*` 属性などが実行されない形にする

## 代替案

- **趣味記事と技術記事を単一の記事一覧にまとめ、絞り込みで分ける** — 実装は減るが、公開サイトの情報設計として趣味と技術を分けたいという要件に合わない。不採用。
- **ページングの代わりに無限スクロールにする** — 体験は滑らかだが、フッターへ到達しにくく、prerender による SEO とも相性が悪い。ページングを採用。

## 受入条件

- [ ] 未ログインで趣味記事の一覧と詳細を閲覧できる
- [ ] 一覧に公開済みの趣味記事のみが表示され、技術記事と下書きが混ざらない
- [ ] 一覧が公開日時の降順で表示される
- [ ] 一覧がページングされ、次のページへ遷移できる
- [ ] タグで一覧を絞り込める
- [ ] 一覧から詳細ページへ遷移し、本文全体が表示される
- [ ] 存在しないスラッグで 404 ページが表示される
- [ ] 下書き記事のスラッグを直接指定しても本文が表示されない
- [ ] 記事本文に含まれるスクリプトが実行されない
- [ ] 記事が 0 件のときに空状態が表示され、エラーにならない
- [ ] モバイル幅で長文が読みやすく表示される

## 対象外

- 記事の全文検索
- コメント、いいね
- 関連記事の表示

## 補足

- 依存: public-web 基盤Issue、記事APIIssue
- 技術記事ページ (`/engineering`) と共通化できるコンポーネントは、両Issueのうち先に着手した側で切り出す
