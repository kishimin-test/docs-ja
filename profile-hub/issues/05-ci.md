## 解決したい課題

既存の GitHub Actions ワークフロー (`ci.yml`, `ci-pr.yml`, `ci-nightly.yml`, `test-coverage.yml`) はルート直下の `backend/` `frontend/` 2 ディレクトリ構成を前提としている。モノレポ再編後はパスが変わり、また `apps/*` が 3 つに増えるため、そのままでは検証が動かない、あるいは無関係なアプリまで毎回ビルドされる。

## 提案する解決策

モノレポ構成に合わせて CI を再構成する。

- 各ワークフローの作業ディレクトリを `apps/public-web` `apps/admin-web` `apps/api` へ更新する
- `paths` フィルタまたは変更検出により、変更のあったワークスペースのみ検証する
- 検証ステップを全アプリで統一する
  1. フォーマット確認
  2. 型チェック (`typecheck`)
  3. Lint (`oxlint` → `eslint`、フロントエンドは `lint:markup` も)
  4. テスト (Small / Medium / Large のサイズ別)
  5. カバレッジ取得とレポート出力
- 独自 ESLint ルールの回帰テストを CI に含める
- Bun のバージョンを固定し、`bun install --frozen-lockfile` を使う
- 現在 main で必須になっている status check と、実際に PR で生成されるジョブ名を一致させる

## 代替案

- **アプリごとに独立したワークフローファイルを作る** — 見通しは良いが、共通ステップの重複が 3 倍になる。matrix によるワークスペース展開を優先して不採用。
- **常に全ワークスペースを検証する** — 設定は単純だが、1 アプリの変更で毎回 3 アプリ分のビルドが走る。変更検出を採用して不採用。

## 受入条件

- [ ] PR 作成時に、変更のあったワークスペースの typecheck / lint / test が実行される
- [ ] 3 アプリすべてで型チェック・Lint・テストが CI から実行できる
- [ ] 独自 ESLint ルールの回帰テストが CI で実行される
- [ ] カバレッジレポートが CI の出力で確認できる
- [ ] main の必須 status check が、PR で実際に生成されるジョブのみで構成されている

## 対象外

- デプロイ (CD) の構築 — 別Issue
- カバレッジ閾値そのものの見直し

## 補足

- 既存ワークフロー: `.github/workflows/ci.yml`, `ci-pr.yml`, `ci-nightly.yml`, `test-coverage.yml`, `copilot-setup-steps.yml`
- テストサイズ (Small / Medium / Large) の分類方針は mojica の `test:small` `test:medium` `test:large` スクリプトに揃える
