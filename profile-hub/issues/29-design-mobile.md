## 解決したい課題

8 つのアートボードはすべて `— Desktop` の幅 1280px 固定で、モバイルのデザインが 1 件も無い。一方で public の各ページIssueはいずれも受入条件に「モバイル幅で崩れずに表示される」を含んでいる。

横方向の padding もページごとに異なる固定値で、どれも 375px では成立しない。

| 画面 | padding (横) | コンテンツ幅 |
| ---- | ------------ | ------------ |
| Home `#2:12`, `#2:20` | 64px | 1152px |
| About `#2:60` | 180px | 920px |
| Hobby `#2:113` | 100px | 1080px |
| Engineering Article `#2:161` | 240px | 800px |
| Contact `#2:198` | 260px | 760px |

Admin も同様で、220px 固定のサイドバー (`#3:18`) と 1060px 固定のメイン (`#3:31`) という構成で、モバイル時のナビゲーション方式が未定義。

モバイルデザインが無いと実装者ごとに独自のブレイクポイントを作ることになり、2 つのアプリで結果が揃わない。

## 提案する解決策

モバイルアートボードを追加し、ブレイクポイントを定義する。

### ブレイクポイント

- ブレイクポイントの区分 (モバイル / タブレット / デスクトップなど) を決め、ピクセル値を記録する
- 固定の横 padding を、ブレイクポイントごとに解決されるコンテナのルールへ置き換える

### 追加するアートボード (375px)

public

- Home
- About
- Hobby 一覧
- Engineering 記事詳細
- Contact

admin

- Login
- Articles
- Article Editor

### 決めること

- public のナビゲーションの折りたたみ方 (ハンバーガーなど) と言語切替の配置
- Admin サイドバーの折りたたみ方と、狭い画面でのナビゲーション到達手段
- デスクトップで 1080×170 の記事一覧行をどう組み直すか
- 記事エディタの 2 カラム (フォーム + 公開設定パネル) の積み重ね順
- タップターゲットのサイズ。タグ・バッジの padding は現在 `6px 10px` または `7px 12px` で高さ約 28〜32px、推奨の 44px を下回る。対象は Hobby のタグフィルター (`#2:118`)、Admin のフィルター (`#3:46`)、`編集 →` (`#3:64`)
- 広告枠のモバイルでの配置 (広告Issue #23 で枠が決まり次第)

## 代替案

- **デスクトップのみ設計し、モバイルは実装で対応する** — 2 つのアプリで実装が分かれ、受入条件を照合する基準が存在しなくなる。不採用。
- **モバイルファーストで設計しデスクトップを導出する** — 原則としては妥当だが、デスクトップのアートボードはすでに存在する。それに合わせてモバイルを追加する。

## 受入条件

- [ ] ブレイクポイントの値が決定され記録されている
- [ ] 8 画面それぞれに 375px のアートボードが存在する
- [ ] コンテナのルールがページごとの固定 padding ではなくブレイクポイント単位で表現されている
- [ ] public のナビゲーションに折りたたみ時のパターンが定義され、言語切替も含まれている
- [ ] Admin のナビゲーションに折りたたみ時のパターンが定義されている
- [ ] 記事一覧行にモバイルでのレイアウトが定義されている
- [ ] 記事エディタにモバイル幅での積み重ね順が定義されている
- [ ] 操作可能なタグ・バッジ・行内アクションがモバイル幅で最小タップターゲットを満たす
- [ ] 375px で文字が切れず、横方向にはみ出さない

## 対象外

- 合意したブレイクポイントを超えたタブレット個別の調整
- まだ存在しない画面 (#31 で扱う)
