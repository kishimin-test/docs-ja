## 解決したい課題

デザインには各コンポーネントの通常状態しか存在しない。フォーカス、ホバー、エラー、ローディング、無効、空状態がいずれも無いが、そのうちいくつかは着手可能なIssueの受入条件にそのまま書かれている。

| 要件 | Issue | デザインの現状 |
| ---- | ----- | -------------- |
| 「キーボードのみでログインが完了できる」 | #13 | フォーカスリングの定義がどこにも無い |
| 「エラーメッセージがスクリーンリーダーに通知される」 | #13 | ログインカード (`#3:3`) にエラー表示の場所が無い |
| 「送信中にボタンが無効化され」 | #13 | ボタン (`#3:15`) にローディング・無効状態が無い |
| 「スラッグが重複したときに該当フィールドへエラーが表示される」 | #14 | Input にエラー状態が無い |
| 「記事が 0 件のときに空状態が表示され」 | #18 | 空状態が無い |

ログインカードは 430×420 固定で、ボタンがすでに下端にある。エラー行を足す前提で設計しない限りレイアウトが崩れる。

プレースホルダーと入力値の区別も無い。ログインのメール欄 (`#3:10`) は `name@example.com` を本文色 `#0E1117` で描画しており、プレースホルダーと実際の入力が見分けられない。必須項目の表示も無い。

## 提案する解決策

共有コンポーネントの操作状態とコンテンツ状態を設計する。

### コンポーネントの状態

- **Input** — 通常、フォーカス、入力済み、エラー (メッセージ付き)、無効、読み取り専用。プレースホルダーは入力値と視覚的に区別する
- **Button** — 通常、ホバー、フォーカス、押下、ローディング、無効。デザインにある 3 種 (濃色プライマリ、淡色セカンダリ、白ターシャリ) すべてを対象にする
- **Link** — 通常、ホバー、フォーカス、訪問済み
- **Tag / Badge** — 操作可能なもの (Hobby のタグフィルター、Admin のフィルター) について通常、選択中、ホバー、フォーカス
- **ナビゲーション項目** — 通常、現在ページ、ホバー、フォーカス。Admin サイドバーには現在状態がある (`EL-62cbb51e`) が、public のナビゲーション (`#2:5`) には無い
- **言語切替** — どちらの言語が有効か (指摘 H-3)

### コンテンツの状態

- 一覧・詳細のローディング
- 空状態 (記事 0 件、経歴なし、お知らせなし)
- API 取得失敗時のエラー
- 404

### フォームの状態

- 必須項目の表示
- フィールド単位のエラーメッセージの配置と、それに合わせたコンテナの伸び方
- フォーム全体のエラーメッセージの配置 (ログイン失敗)
- 削除の確認ダイアログ。#14 と #15 の両方が要求している

### フォーカス

- フォーカスインジケーターのスタイルを 1 つに統一し、使用されるすべての背景に対して検証する
- 2 つのアプリ両方で、キーボード操作時にフォーカスが見えること

## 代替案

- **状態は実装側でコンポーネントライブラリの既定に任せる** — 早いが、フォーカスインジケーターとエラー表示がこのパレットに対して検証されず、#27 のコントラスト対応も引き継がれない。不採用。

## 受入条件

- [ ] Input、Button、Link、Tag、ナビゲーション項目について、フォーカス・ホバー・エラー・ローディング・無効の各状態が設計されている
- [ ] プレースホルダーが入力値と視覚的に区別できる
- [ ] 必須項目が表示されている
- [ ] ログインカードにエラーメッセージの配置が設計され、レイアウトがそれを吸収できる
- [ ] ローディング、空状態、エラー、404 が設計されている
- [ ] 削除の確認ダイアログが設計されている
- [ ] public のナビゲーションに現在ページの状態がある
- [ ] 言語切替が有効な言語を示している
- [ ] フォーカスインジケーターが使用されるすべての背景でコントラスト基準を満たす
- [ ] 各状態が単発のフレームではなくコンポーネントのバリアントとして表現されている
