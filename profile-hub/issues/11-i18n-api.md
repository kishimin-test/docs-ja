# DB コンテンツの多言語対応 (ja/en) を API に実装する

| 項目 | 値 |
| ---- | -- |
| Issue | [#11](https://github.com/kishimin-ai-create/profile-hub/issues/11) |
| 英語タイトル | Serve multilingual database content (ja/en) from the API |
| マイルストーン | v1 |
| ラベル | enhancement,area:api |

---

## 解決したい課題

公開サイトは日本語と英語で表示する必要があるが、記事タイトル・本文・プロフィール・スキル名などのコンテンツは DB に保存されるため、フロントエンドの翻訳ファイルだけでは多言語化できない。API が言語別のコンテンツを返す仕組みが必要になる。

また、翻訳が存在しない言語を要求されたときの挙動 (空を返すか、既定言語へフォールバックするか) を決めないと、英語表示で本文が空のページが公開される。

## 提案する解決策

DB コンテンツの多言語対応を API 側に実装する。

- 対応言語を `ja` / `en` とし、既定言語を決定する
- 翻訳対象を確定する — 記事タイトル・本文・抜粋、プロフィール紹介文・肩書き、スキル名、経歴の説明、お知らせ、カテゴリ・タグ名
- 言語の指定方法を決定する — クエリパラメータ (`?locale=en`) を第一候補とし、`Accept-Language` ヘッダーの扱いも決める
- 未対応の言語コードを指定された場合は、エラーにせず既定言語へフォールバックする
- 翻訳が存在しない項目のフォールバック方針を決定し、実装する
- 管理APIは全言語の翻訳を同時に取得・更新できる形にする (管理画面で日英を並べて編集するため)
- 言語ごとに異なるスラッグを許容するかを決定する (SEO の URL 設計に影響する)

## 代替案

- **フロントエンドの翻訳ファイルのみで対応する** — UI ラベルは対応できるが、記事本文など DB 由来のコンテンツを翻訳できない。不採用。
- **翻訳が無い言語では該当項目を非表示にする** — 実装は単純だが、英語表示で本文が空のページが公開されうる。フォールバック方針の決定を必須とする。

## 受入条件

- [ ] 対応言語、既定言語、言語の指定方法が決定され、`docs/v1/specification/api-specification.md` に記載されている
- [ ] `ja` を指定すると日本語、`en` を指定すると英語のコンテンツが返る
- [ ] 未対応の言語コードを指定してもエラーにならず、既定言語のコンテンツが返る
- [ ] 翻訳が存在しない項目で、決定したフォールバック方針どおりの応答になる
- [ ] 管理APIで 1 リソースの日英両方の翻訳を取得・更新できる
- [ ] 言語を追加する際にテーブル追加が不要である

## 対象外

- フロントエンドの UI ラベル翻訳と言語切替 — 別Issue
- 3 言語目以降の実際の翻訳作業

## 補足

- 依存: データモデルIssue (`Translation` の持ち方)、記事APIIssue、プロフィールAPIIssue
- 縦持ち (`Translation` テーブル) と横持ち (`_ja` / `_en` 列) の選択はデータモデルIssueで決定する
