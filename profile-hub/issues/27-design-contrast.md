## 解決したい課題

アクセントカラー `#F06330` は、小さい文字で使われている箇所すべてで WCAG AA の 4.5:1 を満たしていない。しかもそれが「意味を伝えるラベル」に使われている。WCAG 2.1 の相対輝度式で算出した結果は以下。

| 前景 | 背景 | コントラスト比 | AA (4.5:1) | 使用箇所 |
| ---- | ---- | -------------- | ---------- | -------- |
| `#F06330` | `#FFE8D6` | **2.72:1** | ✗ | `ENGINEERING` / `HOBBY` タグ 12px (`#2:28`, `#2:34`)、`下書き` バッジ 11px (`#3:77`, `#3:84`)、`下書き保存` 11px (`#3:109`) |
| `#F06330` | `#FBFAF5` | **3.08:1** | ✗ | セクション見出しラベル `LATEST` / `ABOUT` / `CAREER` / `SKILLS` / `HOBBY` / `CONTACT` / `TAGS` 12px Bold (`#2:22`, `#2:62` ほか) |
| `#F06330` | `#FFFFFF` | **3.21:1** | ✗ | `未保存の変更があります` 12px (`#3:148`) |
| `#1F8052` | `#E0F7EB` | **4.37:1** | ✗ (僅差) | `公開` バッジ 11px (`#3:63`, `#3:70`) |

このうち 2 件は見た目の問題ではなく機能の問題である。「下書き / 公開」の区別と「未保存の変更があります」という警告は、読めない時点で役割を果たさない。

レンダリング画像でも、下書きバッジと未保存警告が実際に薄く見えることを確認済み。

## 提案する解決策

アクセント色を「装飾用」と「文字用」に分け、文字用を基準を満たすまで暗くする。

- `#F06330` は装飾の塗り、大きな装飾文字、意味を持たないアクセントに限定して残す
- 文字と小さいラベル用に暗いアクセント色を追加し、`#FFE8D6` と `#FBFAF5` の両方に対して 4.5:1 以上であることを検証する
- `公開` バッジで使っている成功色も基準をわずかに下回っているため、同様に扱う
- Figma ファイル内の該当ノードすべてにトークンを適用する
- トークンの組み合わせと実測コントラスト比を記録し、実装と今後のデザイン作業で再利用できるようにする

参考として、既存デザインの中で基準を満たしていることを実測した組み合わせ。

| 前景 | 背景 | 比 |
| ---- | ---- | -- |
| `#5C6375` | `#FBFAF5` | 5.75:1 ✓ |
| `#2E59AD` | `#FBFAF5` | 6.39:1 ✓ |
| `#B2B8C4` | `#0E1117` | 9.57:1 ✓ |
| `#616675` | `#FFFFFF` | 5.73:1 ✓ |

## 代替案

- **文字ではなくバッジの背景を暗くする** — こちらも有効で、下書き・公開バッジには文字色の変更より適している可能性がある。両方を評価してコンポーネントごとに選ぶ。
- **フォントサイズを上げて大きい文字の 3:1 基準を適用する** — 対象は 11〜12px で、小さいことが意図されたラベル。不採用。
- **現状のままにする** — 機能に関わる 2 件 (下書きバッジ、未保存警告) があるため許容できない。

## 受入条件

- [ ] デザイン内のアクセント色の文字とその背景の組み合わせがすべて 4.5:1 以上である
- [ ] `公開` と `下書き` のバッジがどちらも 4.5:1 以上である
- [ ] `未保存の変更があります` の警告が 4.5:1 以上である
- [ ] 装飾用と文字用のアクセントトークンが分離され、名前が付いている
- [ ] トークンの値と実測コントラスト比がデザインドキュメントに記録されている
- [ ] 下書きと公開が色のみに依存せず区別できる

## 対象外

- ホバー・フォーカスなど操作状態のコントラスト (状態デザインのIssueで扱う)
- ビジュアルアイデンティティ全体の変更
