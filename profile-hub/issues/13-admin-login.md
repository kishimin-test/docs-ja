## 解決したい課題

管理者が管理画面へログインする手段がない。認証APIを実装しても、それを利用する画面がなければ記事やプロフィールの管理を開始できない。

## 提案する解決策

`/login` にログイン画面を実装する。

### 表示項目

- メールアドレス入力欄
- パスワード入力欄
- ログインボタン

### 振る舞い

- 認証成功時にダッシュボードへ遷移する
- 認証済みの状態で `/login` を開いた場合はダッシュボードへ遷移する
- 認証失敗時にエラーメッセージを表示する。メールアドレスの存在有無を推測できる文言にしない
- 送信中はボタンを無効化し、二重送信を防ぐ
- 入力検証 — メールアドレスの形式、パスワードの必須。API 呼び出し前にクライアント側でも検証する
- ネットワークエラーとサーバーエラーを区別して表示する
- パスワード欄をブラウザのパスワード管理に対応させる
- キーボードのみで操作でき、エラーメッセージが支援技術に伝わる

## 代替案

- **保護ルートへのアクセス時にモーダルでログインさせる** — 遷移は減るが、直接 URL アクセスやリロード時の挙動が複雑になる。専用ページを採用して不採用。

## 受入条件

- [ ] 正しい認証情報でログインするとダッシュボードへ遷移する
- [ ] 誤った認証情報でエラーメッセージが表示され、ログイン画面に留まる
- [ ] エラーメッセージからメールアドレスの登録有無を判別できない
- [ ] 認証済みで `/login` を開くとダッシュボードへ遷移する
- [ ] メールアドレス未入力・不正形式で送信すると、API を呼ばずに検証エラーが表示される
- [ ] 送信中にボタンが無効化され、連打しても複数回リクエストされない
- [ ] キーボードのみでログインが完了できる
- [ ] エラーメッセージがスクリーンリーダーに通知される

## 対象外

- パスワードリセット、多要素認証
- 管理者アカウントの新規登録画面 (セルフサインアップは設けない)

## デザインレビューによる更新 (2026-09-04)

デザインレビュー (`review/figma-ui-design-20260904.md`) がこの画面に 2 件の問題を検出した。実装前に解消が必要。

- **V-1** — Input コンポーネント `EL-6ce18297` が 520px 固定だが、ログインカードのコンテンツ幅は 350px しかない。描画結果でメール欄とパスワード欄がカード右端で切れている。#28 で追跡
- **H-1** — カードが 430×420 固定でエラーメッセージの居場所が無く、フォーカス・ローディング・無効状態のデザインも無い。#30 で追跡

受入条件に以下を追加する。

- [ ] 対応するすべてのビューポート幅で、入力欄がカード内に収まって描画される
