# 記事管理画面 (一覧・作成・編集・公開/下書き) を実装する

| 項目 | 値 |
| ---- | -- |
| Issue | [#14](https://github.com/kishimin-ai-create/profile-hub/issues/14) |
| 英語タイトル | Implement the article management screens (list, create, edit, publish/draft) |
| マイルストーン | v1 |
| ラベル | enhancement,area:admin-web |

---

## 解決したい課題

記事APIを実装しても、管理者が記事を書いて公開する画面がなければ profile-hub にコンテンツを載せられない。記事管理は管理画面の中心機能であり、これがないと公開サイトが空のまま公開されることになる。

## 提案する解決策

記事管理の画面群を実装する。

### 画面

| パス | 内容 |
| ---- | ---- |
| `/dashboard` | 記事の件数、下書き数、最近更新した記事などの概況 |
| `/articles` | 記事一覧。`type` と `status` での絞り込み、ページング |
| `/articles/new` | 記事の新規作成 |
| `/articles/:id` | 記事の編集 |

### 記事フォームの項目

- タイトル
- スラッグ (タイトルからの自動生成と手動編集)
- `type` — 趣味 / 技術
- 本文
- カテゴリ、タグ
- `status` — 下書き / 公開

### 振る舞い

- 一覧で下書きと公開済みを視覚的に区別できる
- 一覧から公開 / 下書きを切り替えられる
- 削除時に確認ダイアログを表示する。削除は取り消せないことを明示する
- 保存前に公開サイトでの見え方をプレビューできる
- 未保存の変更がある状態で画面を離れようとしたときに警告する
- API の検証エラー (スラッグ重複など) を該当フィールドへ表示する
- 保存中は送信ボタンを無効化し、二重送信を防ぐ
- 日英の記事内容を編集できる

## 代替案

- **一覧から直接インライン編集する** — 画面遷移は減るが、本文のような長文の編集に向かない。専用の編集画面を採用して不採用。
- **削除を論理削除にして確認ダイアログを省く** — 復元は可能になるが、一覧やAPIから除外する処理が全体に波及する。削除方式はデータモデルIssueの決定に従う。

## 受入条件

- [ ] 記事一覧に下書きと公開済みの両方が表示され、状態を区別できる
- [ ] `type` と `status` で一覧を絞り込める
- [ ] 記事を新規作成すると一覧に現れる
- [ ] 記事を編集して保存すると内容が更新される
- [ ] 一覧から公開 / 下書きを切り替えられ、公開サイトでの表示が切り替わる
- [ ] 削除時に確認ダイアログが表示され、キャンセルすると削除されない
- [ ] スラッグが重複したときに該当フィールドへエラーが表示される
- [ ] 未保存の変更がある状態で画面を離れようとすると警告が表示される
- [ ] 保存ボタンを連打しても記事が複数作成されない
- [ ] 日本語と英語の記事内容を編集して保存できる

## 対象外

- 記事内への画像アップロード — v2
- 記事の予約公開、バージョン履歴
- 記事の全文検索

## 補足

- 依存: 記事APIIssue、i18n APIIssue、admin-web 基盤Issue

## デザインレビューによる更新 (2026-09-04)

### デザインが確定させた事項

- 本文欄は `本文（Markdown）` (`#3:137`) → 執筆形式は **Markdown**
- 日英は **言語タブ** (`#3:112`〜`#3:116`) で切り替える。画面を分けない
- 一覧のフィルターは `すべて / 趣味 / 技術 / 公開 / 下書き` (`#3:46`〜`#3:56`) = type + status
- ダッシュボードの指標は 全記事 / 公開中 / 下書き (`#3:36`〜`#3:45`)

### デザイン側で解消が必要な不足

- **H-7** — 一覧行 (`#3:57`) に `編集 →` しか無い。削除操作も確認ダイアログも無く、公開/下書きバッジは表示のみで操作できない
- **V-2** — Markdown 本文欄 (`#3:138`) が単行 Input の `alignItems: center` を流用しており、文字が縦中央に描画される。複数行は上揃えにする
- **V-1** — `タイプ` と `ステータス` の Input (`#3:130`, `#3:134`) が 254px の枠に 520px で配置され切れている
- **V-7** — 一覧カードが 480px 固定で、4 行の下に約 128px の空白が残る。行数に応じて可変にし、空状態を設計する
- **V-9** — 公開設定パネル (`#3:144`) が公開日時とカテゴリを静的テキストで表示しており、入力 UI になっていない。400px 以上の空白もある

受入条件に以下を追加する。

- [ ] Markdown 本文欄が枠の上端から文字を表示する
- [ ] 記事件数が少ないときに一覧カードへ大きな空白が出ず、0 件で空状態を表示する

`/dashboard` のデザインはまだ存在しない。#31 を参照。
