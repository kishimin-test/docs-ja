## 解決したい課題

公開サイトは日本語と英語で表示する必要があるが、UI ラベルも URL 設計も日本語固定で実装すると、後から多言語化する際に全ページとルーティングの作り直しになる。

また、言語ごとに URL が分かれていない場合、検索エンジンが日英を別ページとして扱えず、英語圏からの流入が期待できない。

## 提案する解決策

公開サイトの i18n (ja / en) を実装する。

### 決めること

- URL 設計 — パス接頭辞 (`/en/about`) を第一候補とし、既定言語 (ja) を接頭辞なしにするか統一するかを決める
- 初回アクセス時の言語決定 — `Accept-Language` による判定を行うか、既定言語で固定するか
- 選択した言語の保持方法

### 実装

- UI ラベル (ナビゲーション、ボタン、日付書式、空状態、エラーメッセージ) の翻訳リソースを言語別に管理する
- DB 由来のコンテンツは、公開APIへ言語を指定して取得する
- ヘッダーに言語切替を設置する。切り替え時は同じページの対応する言語版へ遷移し、トップへ戻らない
- `html` 要素の `lang` 属性を選択中の言語に合わせる
- 日付・数値の書式を言語に合わせる
- 翻訳キーの欠落を検出できるようにする (未翻訳キーがそのまま画面に出ないようにする)
- SEO Issue と連携し、`hreflang` と言語別の正規 URL を出力できる状態にする

## 代替案

- **クエリパラメータで言語を指定する (`?lang=en`)** — 実装は単純だが、検索エンジンが別ページとして扱いにくく、共有された URL の言語が保持されにくい。パス接頭辞を第一候補とする。
- **ブラウザの言語設定のみで自動切替し、切替 UI を設けない** — 利用者が明示的に言語を選べない。切替 UI を設ける。

## 受入条件

- [ ] URL 設計と初回アクセス時の言語決定方式が決定され、記録されている
- [ ] 全ページを日本語と英語で表示できる
- [ ] 言語ごとに URL が分かれている
- [ ] 言語切替で、同じページの対応する言語版へ遷移する
- [ ] 言語を切り替えた状態でリロードしても、その言語が維持される
- [ ] 記事本文・プロフィールなど DB 由来のコンテンツが選択した言語で表示される
- [ ] `html` 要素の `lang` 属性が選択中の言語と一致する
- [ ] 日付が言語に応じた書式で表示される
- [ ] 未翻訳の項目で、翻訳キーがそのまま画面に表示されない
- [ ] 存在しない言語コードの URL でエラーにならず、既定言語または 404 として扱われる

## 対象外

- 管理画面 (admin-web) の多言語化
- 3 言語目以降の追加
- 翻訳文そのものの作成

## 補足

- 依存: public-web 基盤Issue、i18n APIIssue
- SEO Issue の `hreflang` / 正規 URL と整合させる
- next-intl は Next.js 前提のため使用しない。Vite + React で動作する i18n ライブラリを選定する

デザインレビュー (`review/figma-ui-design-20260904.md`) の検出事項。

- **H-3** — 言語切替が `JA / EN` という 1 テキストノード (`#2:11`) で、現在の言語表示も無く、2 つの操作要素に分かれてもいない
