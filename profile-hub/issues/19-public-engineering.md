## 解決したい課題

技術記事を訪問者が読む手段がない。エンジニアページは、採用担当者や同業者が技術的な関心・経験を判断する材料になる。

## 提案する解決策

技術記事の一覧ページ (`/engineering`) と詳細ページ (`/engineering/:slug`) を実装する。

### 一覧ページ (`/engineering`)

- 公開済みで `type = engineering` の記事を、公開日時の降順で表示する
- 表示項目 — タイトル、抜粋、公開日、タグ
- ページングを適用する
- タグによる絞り込み

### 詳細ページ (`/engineering/:slug`)

- 表示項目 — タイトル、本文、公開日、更新日、タグ
- 一覧へ戻る導線
- コードブロックが読みやすく表示される (等幅フォント、横スクロール、必要ならシンタックスハイライト)
- 長いコード行がページ全体の横スクロールを起こさない
- 存在しないスラッグ、または下書き記事のスラッグを指定した場合は 404 を表示する

### 共通化

- 趣味記事ページと共通する一覧・詳細の表示ロジックはコンポーネントとして共有し、`type` を切り替えて使う
- `type` を増やしたときに新しい一覧・詳細ページを最小の追加で作れる構造にする

## 代替案

- **趣味記事ページのコードを複製する** — 早いが、以後の修正が 2 箇所に分かれる。共通コンポーネント化を採用して不採用。

## 受入条件

- [ ] 未ログインで技術記事の一覧と詳細を閲覧できる
- [ ] 一覧に公開済みの技術記事のみが表示され、趣味記事と下書きが混ざらない
- [ ] 一覧が公開日時の降順で表示され、ページングされる
- [ ] タグで一覧を絞り込める
- [ ] 詳細ページで本文全体が表示される
- [ ] コードブロックが等幅で表示され、長い行がページ全体の横スクロールを起こさない
- [ ] 存在しないスラッグで 404 ページが表示される
- [ ] 下書き記事のスラッグを直接指定しても本文が表示されない
- [ ] 記事本文に含まれるスクリプトが実行されない
- [ ] 一覧・詳細の表示ロジックが趣味記事ページと共有されている
- [ ] モバイル幅で崩れずに表示される

## 対象外

- 記事の全文検索
- コメント、いいね
- 関連記事の表示

## 補足

- 依存: public-web 基盤Issue、記事APIIssue、趣味記事ページIssue (共通コンポーネント)
