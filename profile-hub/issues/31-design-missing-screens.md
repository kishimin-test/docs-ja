## 解決したい課題

設計済みの画面は 8 枚だが、v1 に必要なのは約 16 枚。Issue が求めているもののおよそ半分にデザインが存在しない。

| 要件 | Issue | デザイン |
| ---- | ----- | -------- |
| `/` Home | #17 | ✅ `#2:2` |
| `/about` | #17 | ✅ `#2:50` |
| `/hobby` 一覧 | #18 | ✅ `#2:103` |
| `/hobby/:slug` 詳細 | #18 | ❌ |
| `/engineering` 一覧 | #19 | ❌ |
| `/engineering/:slug` 詳細 | #19 | ✅ `#2:151` |
| `/contact` | #20 | ✅ `#2:188` |
| 404 | #16 | ❌ |
| 空状態 / エラー / ローディング | #16 #17 #18 | ❌ |
| `/login` | #13 | ✅ `#3:2` |
| `/dashboard` | #14 | ❌ (サイドバーに項目のみ) |
| `/articles` | #14 | ✅ `#3:17` |
| `/articles/:id` | #14 | ✅ `#3:86` |
| `/profile` | #15 | ❌ |
| `/settings` | #15 | ❌ |

不足の仕方も非対称で、Hobby は一覧だけ、Engineering は詳細だけがある。#19 は一覧・詳細の表示ロジックを両者で共有することを求めているが、それぞれ片方しか無い状態では判断できない。

## 提案する解決策

不足している画面を設計する。

### public

- **Hobby 記事詳細** — Engineering 詳細に揃える。コードブロックの扱いは不要
- **Engineering 一覧** — Hobby 一覧に揃える。共通コンポーネントが明確になるよう Hobby 詳細と同時に設計する
- **404** — 共通レイアウトに沿い、サイト内へ戻る導線を持つ

### admin

- **`/dashboard`** — 指標 (全記事・公開中・下書き) は記事画面の統計カード (`#3:36`〜`#3:45`) からすでに読み取れる。それ以外に何を置くか (最近更新した記事、クイックアクション) を決める
- **`/profile`** — プロフィール、経歴、スキル、SNSリンクの追加・編集・削除・並び替え。並び替えはキーボードで操作できる形として示す
- **`/settings`** — お知らせ管理とサイト設定

### 共通

- 空状態・ローディング・エラー。状態デザインIssue (#30) と揃える

### 決めること

サイドバーの `Media` 項目 (`#3:28`, `#3:97`) を v1 で表示するかどうか。メディア管理は v2 のため、非表示にするか無効状態として設計する。

## 代替案

- **デザインなしで既存パターンに沿って実装する** — 単純な画面なら成立するが、`/profile` と `/settings` は並び替えと入れ子リソースを含み、推測ではなく決定が必要。この 2 画面については不採用。Hobby 詳細と Engineering 一覧は対になる画面が存在するため、確認程度で足りる。

## 受入条件

- [ ] Hobby 記事詳細が設計されている
- [ ] Engineering 一覧が設計されている
- [ ] 404 ページが設計されている
- [ ] Admin ダッシュボードが設計されている
- [ ] Admin プロフィール管理画面が、並び替えを含めて設計されている
- [ ] Admin 設定・お知らせ画面が設計されている
- [ ] 一覧・詳細ページの空状態、ローディング、エラーが設計されている
- [ ] Hobby と Engineering で共有する一覧・詳細の表示が共通コンポーネントとして表現されている
- [ ] `Media` を v1 のサイドバーに出すかが決定され反映されている
