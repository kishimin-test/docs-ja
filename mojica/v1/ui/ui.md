# mojica MVP UI設計書

## 1. 概要

mojicaのMVPでは、文字アート画像を生成するためのWeb UIを提供する。

ユーザーは1画面上で必要な情報を入力し、画像の種類を選択して画像を生成できる。

生成された画像はプレビューを表示せず、自動的にダウンロードする。

UIはレスポンシブ対応とし、PC・タブレット・スマートフォンから利用できるようにする。

---

# 2. 画面一覧

MVPでは画像生成画面と404 Not Found画面を提供する。

| 画面              | 概要                                       |
| ----------------- | ------------------------------------------ |
| 画像生成画面       | 文字・色・画像種類を指定して画像を生成する |
| 404 Not Found画面 | 存在しないパスへアクセスした場合に表示する |

---

# 3. ヘッダー

画面上部にヘッダーを配置する。

ヘッダー左側にmojicaのロゴ（角丸スクエアのシンボル + 「mojica」ワードマーク）を配置する（§15「アクセシビリティ」参照）。

ヘッダー右側には言語切り替えUIを配置する。選択中の言語名と展開アイコンを表示するドロップダウン形式とする。

対応言語：

- 日本語
- English

選択された言語に応じて、UI表示とmojica APIへの `Accept-Language` を切り替える。

日本語：

```http
Accept-Language: ja
```

英語：

```http
Accept-Language: en
```

# 5. 入力項目

## 描画する文字列

文字アートとして描画する文字列を入力する。

例：

```text
KA
```

入力形式：

`text`

制約：

- 必須
- 1文字以上
- 64文字以下
- 空白文字のみの入力は禁止
- 制御文字は禁止

---

## 描画に使う文字

描画する文字列を構成するために使用する文字を入力する。

例：

```text
🌻
```

入力形式：

`text`

制約：

- 必須
- 1文字以上
- 128文字以下
- 制御文字は禁止
- 空白文字のみの入力は許可する

---

## 描画文字色

描画に使用する文字の色を指定する。

カラーピッカーを使用する。

フロントエンドではHEX形式で値を保持する。

例：

```text
#FFD400
```

mojica APIへHEX形式で送信する。

---

## 敷き詰める文字

描画文字の周囲に敷き詰める文字を入力する。

例：

```text
☀
```

入力形式：

`text`

制約：

- 必須
- 1文字以上
- 128文字以下
- 制御文字は禁止
- 空白文字のみの入力は許可する

ただし、「描画に使う文字」と「敷き詰める文字」の両方を空白文字のみにはできない。

---

## 敷き詰める文字色

敷き詰める文字の色を指定する。

カラーピッカーを使用する。

フロントエンドではHEX形式で値を保持する。

例：

```text
#FF69B4
```

mojica APIへHEX形式で送信する。

---

# 6. 画像種類

画像の種類はセレクトボックスで選択する。

選択肢は以下とする。

| 表示          | APIの値        |
| ------------- | -------------- |
| 標準画像      | `standard`     |
| X背景画像     | `x-background` |
| Xアイコン画像 | `x-icon`       |

初期値は `standard` とする。

---

# 7. 画像生成ボタン

入力フォームの下部中央に、大きな画像生成ボタンを配置する。

ボタンの表示：

```text
画像を生成する
```

ボタン押下時に `POST /images` を実行する。

直前の生成がAPIエラーで失敗している場合の見た目（Retryableバリアント）は§12「APIエラー表示」で定義する。

---

# 8. 画像生成フロー

ユーザーは以下の順序で画像を生成する。

1. 描画する文字列を入力する
2. 描画に使う文字を入力する
3. 描画文字色を選択する
4. 敷き詰める文字を入力する
5. 敷き詰める文字色を選択する
6. 画像種類を選択する
7. 「画像を生成する」を押す
8. `POST /images` を実行する
9. PNG画像を取得する
10. 自動でダウンロードする

画像生成後のプレビューはMVPでは提供しない。

---

# 9. 生成中

画像生成APIへのリクエスト中は、画像生成ボタンを無効化する。

表示を以下に変更する。

```text
生成中...
```

生成中の多重リクエストを防止する。

処理完了またはエラー発生後、ボタンを再度有効化する。

---

# 10. ダウンロード

画像生成に成功した場合、取得したPNG画像を自動的にダウンロードする。

ユーザーによる追加操作は不要とする。

MVPでは以下を提供しない。

- 画像プレビュー
- 手動ダウンロードボタン
- 生成履歴
- 画像のサーバー保存

---

## API側のバリデーションエラー

APIから `422 Unprocessable Entity` が返却された場合は、`errors[].field` を利用して対応する入力項目付近にエラーを表示する。

フロントエンドのバリデーションを通過した場合でも、API側のバリデーションを最終的な正とする。

# 12. APIエラー表示

フィールドに紐づかないエラーは、入力フォームカードの先頭（各入力項目より上）に表示する。

| ステータス | 表示内容               |
| ---------- | ---------------------- |
| 400        | リクエストエラー       |
| 429        | リクエスト回数超過     |
| 500        | サーバーエラー         |
| 502        | 画像生成サービスエラー |
| 504        | タイムアウト           |

表示例：

```text
画像の生成に失敗しました。
時間をおいて再度お試しください。
```

APIから返却されたローカライズ済みの `message` をユーザーへ表示する。

内部エラー情報は表示しない。

APIエラー発生後は、画像生成ボタンの見た目を再試行を促す配色（Retryableバリアント）に変更する。表示文言・押下時の挙動（`POST /images`の再実行）は通常時と同じとする。

## 429の`Retry-After`

APIレスポンスに`Retry-After`ヘッダー（再試行可能になるまでの秒数）が含まれる場合、画像生成ボタンをその秒数だけ`disabled`にし、1秒ごとに更新するカウントダウン表示に切り替える。

```text
{秒数}秒後に再試行できます
```

カウントダウンが0になったら、ボタンを有効化し、通常の「画像を生成する」（Retryableバリアント）表示へ戻す。バナー本体の表示文言（APIから返却された`message`）は変更しない。カウントダウンはクライアント側のタイマーで行い、APIへの追加リクエストは発生しない。

`Retry-After`ヘッダーが含まれない場合は、ボタンは無効化せず、通常通り即座に再試行できる。

i18n対応時の英語表示例：

```text
You can try again in {seconds} seconds
```

# 13. i18n

UIは日本語と英語の切り替えに対応する。

言語切り替えUIはヘッダー右側に配置する。

切り替え対象には以下を含む。

- 入力項目のラベル
- ボタン
- セレクトボックスの表示名
- フロントエンドのバリデーションメッセージ
- APIエラーメッセージ
- 生成中などの状態表示

日本語選択時は、

```http
Accept-Language: ja
```

英語選択時は、

```http
Accept-Language: en
```

をmojica APIへ送信する。

---

# 14. レスポンシブ対応

PC・タブレット・スマートフォンに対応する。

フォームは基本的に1カラムで構成する。

PCではフォームの最大幅を設定して中央に配置する。

スマートフォンでは利用可能な画面幅に合わせてフォームを広げる。

横スクロールが発生しないことを基本とする。

ヘッダーでは、ロゴ画像と言語切り替えUIが小さい画面でも適切に表示・操作できるようにする。

---

# 15. アクセシビリティ

フォームの各入力項目には対応するラベルを設定する。

キーボードのみでも以下の操作を行えるようにする。

- 入力
- カラー選択
- 画像種類の選択
- 言語切り替え
- 画像生成

エラー表示は色だけに依存せず、テキストでも内容を伝える。

画像生成中はボタンの表示と状態を変更し、処理中であることをユーザーへ伝える。

入力エラーがある場合は、該当フィールドとエラーメッセージをアクセシブルに関連付ける。

ロゴは角丸スクエアのシンボル（装飾）と「mojica」のワードマークテキストで構成し、`<img>`は使用しない。シンボル部分は`aria-hidden="true"`とし、可視テキスト「mojica」がアクセシブルネームを担う。

# 17. MVP対象外

以下はMVPでは実装しない。

- 画像プレビュー
- 任意の画像サイズ指定
- 生成履歴
- ログイン
- ユーザー情報の保存
- SNSへの直接共有
- 生成画像のサーバー保存
- 画像から文字を敷き詰める機能

# 18. MVPのUIゴール

ユーザーが1画面上で、

「文字を入力する → 色を選ぶ → 画像種類を選ぶ → 画像を生成する」

という最小限の操作だけで文字アート画像を生成し、PNG画像を取得できるUIを提供する。

# 20. 予期しないエラー画面

レンダリング中に予期しない例外が発生した場合に表示する、ErrorBoundaryのfallback画面。

404画面と異なり、ヘッダー・フッターは表示しない。ErrorBoundaryはアプリのルートで`I18nProvider`より外側に配置し、i18nの仕組み自体が例外の原因であっても表示できるようにする（component-design.md参照）。そのため表示文言は`I18nProvider`のReact Contextに依存せず、`localStorage`に保存されたロケール値を直接読み取り、画面内に埋め込んだja/en辞書から選択する。

見出し：

```text
エラーが発生しました
```

説明文：

```text
予期しない問題が発生しました。しばらくしてからページを再読み込みしてください。
```

ボタン：

```text
ページを再読み込み
```

ボタン押下時はクライアントサイドルーティングではなく、ブラウザの通常のページ再読み込み（`window.location.reload()`相当）を行う。Reactの状態自体が壊れている可能性があるため、アプリ内遷移では復旧を保証できないため。mojica APIへのリクエストは発生しない。

i18n対応時の英語表示例：

```text
An error occurred
```

```text
Something unexpected happened. Please reload the page and try again.
```

```text
Reload page
```
