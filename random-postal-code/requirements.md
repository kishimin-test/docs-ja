# 1. 概要

## 1.1 システム概要

Zipnami は、日本全国の郵便番号から1件をランダムに選択し、その郵便番号に対応する住所と地図を表示するサービスである。

一般的な住所検索サービスのように利用者が目的地を指定するのではなく、ランダムな郵便番号を起点として、日本の知らない場所と偶然出会う体験を提供する。

## 1.2 名称

「Zipnami」は、

- ZIP：郵便番号
- nami：波

を組み合わせた名称である。

波に流されるように、日本のどこかへ偶然たどり着く体験を表現する。

## 1.3 背景

一般的な住所・地図サービスは、利用者が目的地や住所を指定し、その場所を検索することを目的としている。

一方、Zipnamiでは目的地を利用者自身が決めない。

ランダムに選ばれた郵便番号を入口として、普段であれば検索することのない地域を知る機会を提供する。

## 1.4 目的

Zipnamiでは以下を実現する。

- 日本全国の知らない場所と偶然出会えること
- 1回の操作でランダムな郵便番号を取得できること
- 郵便番号に対応する住所を確認できること
- 住所を地図で確認できること
- 過去に生成した場所を簡単に振り返れること
- アカウント登録なしですぐ利用できること

## 1.5 対象バージョン

Zipnamiは段階的に提供する。

### V1（MVP）

Web版を提供する。

Zipnamiのコア体験である、

> ランダムな郵便番号を生成し、その住所と地図を見る

ことを実現する。

### V2

V1のWeb版を維持したまま、Androidアプリを追加する。

AndroidでもWeb版と同様のランダム探索体験を提供する。

## 1.7 システム利用者

本システムの利用者は一般ユーザーとする。

ユーザー登録およびログインは必要としない。

## 1.8 前提条件

- 日本国内の郵便番号を対象とする
- 郵便番号データには日本郵便の公開データを使用する
- 郵便番号データは事前にZipnami用へ加工する
- 実行時に住所取得のための外部APIへ依存しない
- ユーザーアカウントを持たない
- 現在位置を取得しない

# 2. 業務要件

## 2.1 業務概要

Zipnamiは業務システムではなく一般利用者向けサービスである。

そのため、本書では利用者によるZipnamiの利用行動を業務として扱う。

主な利用行動は以下とする。

1. Zipnamiを開く
2. ランダム生成を実行する
3. 郵便番号を確認する
4. 住所を確認する
5. 地図を確認する
6. 必要に応じて再生成する
7. 過去の生成履歴を確認する

## 2.2 V1 業務フロー

```text
Zipnamiへアクセス
        │
        ▼
ランダム生成
        │
        ▼
郵便番号を抽選
        │
        ▼
郵便番号・住所を表示
        │
        ├──────────────┐
        ▼              ▼
   地図を確認       履歴へ保存
        │
        ▼
必要に応じて再生成
```

## 2.3 V2 業務フロー

```text
Androidアプリを起動
        │
        ▼
ランダム生成
        │
        ▼
郵便番号・住所を取得
        │
        ├──────────────┐
        ▼              ▼
 「地図で見る」      履歴へ保存
        │
        ▼
外部地図サービス
```

## 2.4 ランダム生成

利用者がランダム生成を実行すると、日本全国の一意な郵便番号から1件を選択する。

すべての一意な郵便番号について選択確率を同一とする。

住所レコード数によって選択確率が変化してはならない。

同じ郵便番号が複数回生成されることは許容する。

## 2.5 住所確認

生成された郵便番号に対応する住所を確認できること。

同一郵便番号に複数の住所が存在する場合は、該当するすべての住所を確認できること。

## 2.6 地図確認

### V1

Web上で生成された住所を地図で確認できること。

また、外部のGoogle Mapsで住所を開けること。

### V2

Androidでは住所から外部地図アプリまたはブラウザを起動できること。

V2ではAndroidアプリ内に地図を埋め込まない。

## 2.7 履歴確認

利用者は過去に生成した結果を確認できること。

履歴は以下のルールとする。

- 最大20件
- 新しい順
- 21件目追加時は最古の1件を削除
- 同一郵便番号の重複を許可
- サーバーへ保存しない
- WebとAndroid間で同期しない

## 2.8 利用場所

### V1

Webブラウザから利用する。

以下の端末サイズを対象とする。

- Desktop
- Tablet
- Smartphone

### V2

V1に加えてAndroid端末から利用できる。

## 2.9 利用時間

原則として24時間利用可能とする。

計画停止または利用している外部サービスの障害時を除く。

## 2.10 業務規模

不特定多数の一般利用者による利用を想定する。

V1では大規模アクセスを前提とした専用インフラは構築しないが、利用者増加に応じて拡張可能なサービス構成とする。

## 2.11 システム化対象外

V1・V2とも以下を対象外とする。

- ユーザー登録
- ログイン
- ユーザー管理
- サーバー側履歴
- お気に入り
- SNS投稿
- 郵便番号検索
- 都道府県指定
- 市区町村指定
- GPS
- 現在位置取得
- プッシュ通知
- 課金
- iOS
- 多言語対応

V1ではAndroidアプリも対象外とする。

## 3.2 V1（MVP）機能要件

### F-001 ランダム郵便番号生成

利用者が「ランダム生成する」を実行すると、一意な郵便番号一覧から1件をランダムに選択する。

抽選対象は元データの住所レコードではなく、一意な郵便番号とする。

### F-002 郵便番号表示

生成された郵便番号を以下の形式で表示する。

```text
XXX-XXXX
```

### F-003 住所表示

生成された郵便番号に対応する住所を表示する。

住所は以下の情報から構成する。

- 都道府県
- 市区町村
- 町域

同一郵便番号に複数住所が存在する場合はすべて表示する。

### F-004 郵便番号コピー

表示された郵便番号をクリップボードへコピーできること。

### F-005 地図表示

WebではGoogle Mapsを利用して住所の地図を表示する。

複数住所が存在する場合は地図表示対象の住所を選択できること。

初期状態では先頭住所を地図へ表示する。

### F-006 外部地図起動

表示されている住所をGoogle Mapsで開くことができる。

### F-007 履歴表示

生成結果をブラウザ内に保存し、一覧表示できる。

最大20件とする。

履歴は新しい順に表示する。

### F-008 Web広告

Web版では広告を表示する。

広告はZipnamiの主要操作を妨げない位置へ配置する。

広告の読み込みに失敗しても主要機能を継続して利用できること。

### F-009 エラー表示

利用者へ理解可能なエラーを表示する。

対象には以下を含む。

- 郵便番号生成失敗
- 通信失敗
- 地図表示失敗
- 外部地図起動失敗
- コピー失敗

再試行可能な処理については再試行手段を提供する。

### F-010 プライバシー表示

Web上からプライバシーポリシーを確認できること。

Androidアプリから最低限以下を確認できること。

- アプリ名
- プライバシーポリシー
- 郵便番号データの出典

# 5. 情報・データ要件

## 5.1 郵便番号データ

日本郵便が公開する郵便番号データを使用する。

実行時に日本郵便から住所データを取得しない。

事前にZipnamiで利用可能な形式へ変換する。

## 5.2 データ構造

1つの一意な郵便番号に対して、1件以上の住所を保持できること。

論理構造は以下とする。

```text
PostalCode
 ├─ postalCode
 └─ addresses
      ├─ address
      ├─ address
      └─ ...
```

各住所は最低限以下を持つ。

```text
都道府県
市区町村
町域
```

## 5.3 正規化

日本郵便の元データを郵便番号単位でグループ化する。

同一郵便番号に対応する住所はすべて保持する。

完全に同一の住所のみ重複除去する。

複数住所を1つの住所文字列へ統合しない。

正規化後は一意な郵便番号につき1つの郵便番号データとする。

## 5.4 抽選母集団

ランダム抽選の母集団は正規化後の一意な郵便番号とする。

住所数や元データのレコード数によって抽選確率を変化させない。

## 5.5 履歴データ

履歴は利用端末内に保存する。

最大20件とする。

サーバー側には保存しない。

# 6. 外部インターフェース要件

## 6.1 郵便番号生成サービス

WebおよびV2のAndroidからランダムな郵便番号・住所を取得できるインターフェースを提供する。

詳細なURL、HTTP方式、JSONスキーマ等はAPI設計で定義する。

## 6.2 Google Maps

V1 WebではGoogle Mapsを利用する。

利用に必要な認証情報について適切な利用元制限および利用API制限を設定する。

地図サービスが利用できない場合でも郵便番号・住所は表示できること。

## 6.3 Web広告サービス

V1からWeb広告サービスを利用する。

広告サービスによる障害をZipnami本体から分離する。

## 6.4 Android広告サービス

V2ではAndroid向け広告サービスを利用する。

広告サービスによる障害をZipnami本体から分離する。

# 7. 非機能要件

## 7.1 可用性・信頼性

原則24時間利用可能とする。

ただし、計画停止、基盤サービス障害、外部サービス障害等を除く。

地図または広告サービスに障害が発生した場合でも、ランダム生成および住所表示は継続可能とする。

重大なエラーが発生しても、可能な範囲で再試行できる状態を維持する。

## 7.2 性能

ランダム生成から郵便番号・住所表示まで、通常利用において待ち時間を意識させない応答を目標とする。

郵便番号抽選処理では外部住所APIへアクセスしない。

地図および広告の読み込み完了を結果表示の条件としない。

## 7.3 拡張性

利用者数の増加に応じてサービスを拡張できること。

V1のWebとV2のAndroidから同じ郵便番号生成サービスを利用できること。

将来的なiOS等のクライアント追加を妨げないこと。

## 7.4 ユーザビリティ

Zipnamiの主要操作は「ランダム生成する」の1操作を中心とする。

初めて利用するユーザーでも説明書なしで主要機能を利用できることを目標とする。

## 7.5 アクセシビリティ

Webでは最低限以下を満たす。

- キーボードで主要操作が可能
- 操作要素の意味が理解できる
- 色だけで状態を伝えない
- フォーカス位置を確認できる
- エラーをテキストで確認できる
- 広告とサービス機能を区別できる

## 7.6 セキュリティ

V1・V2ではユーザー認証を必要としない。

秘密情報をWebブラウザまたはAndroidアプリへ不必要に公開しない。

公開が必要な外部サービス用キーには、サービス提供者が提供する利用元・API等の制限を設定する。

通信はHTTPSを使用する。

## 7.7 プライバシー

Zipnami自身は以下をサーバー側のユーザーデータとして保存しない。

- 氏名
- メールアドレス
- 電話番号
- 現在位置
- 位置情報
- ユーザーアカウント
- 生成履歴
- 広告識別子

外部サービスまたはSDKによるデータ処理については、Zipnami自身によるデータ保存と区別してプライバシーポリシーへ記載する。

## 7.8 広告・Consent

広告サービスが必要とするConsentについて、適用法令および広告プラットフォームの要件に従う。

Consentが得られない場合またはConsent処理が失敗した場合でも、Zipnamiの主要機能は利用可能とする。

V2ではAndroidで実際に使用するSDKと設定に基づいてGoogle PlayのData Safetyを申告する。

## 7.9 互換性

### V1

以下の画面サイズを対象とする。

- Desktop
- Tablet
- Smartphone

主要なモダンブラウザで利用可能とする。

### V2

V1に加えてAndroidを対象とする。

iOSは対象外とする。

## 7.10 運用・保守性

郵便番号データを日本郵便の公開データ更新に合わせて更新可能とする。

外部サービスの仕様変更に対応可能とする。

障害発生時に原因を調査できること。

## 7.11 移行性

V1は新規サービスのため、既存システムからのユーザーデータ移行は存在しない。

V2でもWebのユーザーデータをAndroidへ移行・同期しない。

V1からV2への移行時には既存Webサービスを継続して利用可能とする。

## 7.12 システム環境

V1はWebブラウザから利用できるインターネットサービスとして提供する。

V2ではAndroidアプリを追加する。

具体的なクラウドサービス、フレームワーク、プログラミング言語、ディレクトリ構成、ビルド方式等は基本設計書で定義する。

# 8. V1（MVP）受入条件

V1は以下を満たした場合に受入可能とする。

- [ ] WebからZipnamiを利用できる
- [ ] ランダムな郵便番号を生成できる
- [ ] 一意な郵便番号単位で抽選される
- [ ] 住所レコード数によって抽選確率が変化しない
- [ ] 郵便番号を表示できる
- [ ] 郵便番号に対応するすべての住所を表示できる
- [ ] 郵便番号をコピーできる
- [ ] 住所を地図で確認できる
- [ ] 外部Google Mapsで住所を開ける
- [ ] 地図障害時にも郵便番号・住所を確認できる
- [ ] 履歴を新しい順で確認できる
- [ ] 履歴が最大20件に制限される
- [ ] 21件目追加時に最古の履歴が削除される
- [ ] Web広告を表示できる
- [ ] 広告障害時にも主要機能を利用できる
- [ ] 必要なConsent処理を行える
- [ ] プライバシーポリシーを確認できる
- [ ] Desktop / Tablet / Smartphoneで利用できる
- [ ] エラー後に主要操作を再試行できる
- [ ] 本番Webサービスとして公開できる

AndroidはV1の受入条件に含めない。
